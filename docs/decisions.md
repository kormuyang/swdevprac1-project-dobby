## D-54: Restore focused middleware and shared errors

User, November 16: restore route validation and approved-provider middleware. Store normalized body/query/params in `req.validated`, leaving Express request properties untouched. Use a small `AppError(status, message)` class for expected failures and one JSON error handler for controller, parser and framework errors. Controllers forward failures with `next(error)`; keep transaction checks. Retain the global rate limit only, provider naming, named imports, resource routers and global `express.json()`. Supersedes the placement/error policies in D-48–D-50 and D-52.

## D-55: One shared database

User, November 16: use only MONGO_URI and the same database for the app, integration tests, seed/reset and performance checks. Use the explicit database name dobby for setup/test guards. This replaces A/B/test database isolation. Run integration files sequentially; retain fixture-scoped cleanup and transaction races within individual tests. Performance still requires an empty database; reset deletes the shared database only with ALLOW_TEST_DB_RESET=true. No database is modified by this source change.

## D-56: Consistent feature modules and request handling

User, November 16: fix the seven code consistency findings. Handle known parser failures with safe client statuses, forward authentication failures to the shared error handler, use one normalized ObjectId validator, keep lifecycle input rules pure and authorization in routes, move public provider discovery into provider modules, use the shared Bangkok date helper and remove unused validation time input. CLI tools load .env only in their entry points. Keep current URLs: /providers is public discovery, /provider/... is the authenticated representative workspace, and /admin/providers is admin management. These prefixes describe access contexts, not different business entities.

## D-57: First-level route mounts in server.js

User, November 16: expose the first API path segment in server.js instead of mounting resource routers at /api/v1. Use six flat routers: auth, providers, vehicles, bookings, provider and admin. Each router declares paths relative to its mount; representative and admin routers collect their respective workspace operations. Keep existing endpoint URLs, named controller imports, router.route() chains and route-scoped middleware. This replaces the four-file mount structure of D-53 without changing the OpenAPI interface.

## D-58: Consolidate feature services

User, November 16: move cancelNonCompletedForProvider from bookingCancellation.js into services/bookings.js, and requireApprovedProvider from providerAccess.js into services/providers.js. Remove the two single-function files and update callers/tests. Keep bulk provider cancellation distinct from customer/admin cancellation, including its caller-owned transaction, same-session writes and provider → sorted users → sorted vehicles guard order. Keep the approval guard reusable from middleware and in-transaction vehicle writes.
